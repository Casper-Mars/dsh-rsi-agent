# 任务程序创作规范（task-authorship）

本规范约束「一次性任务程序」的结构与返回契约。它是固件：只读，不参与自身进化。

## 结构契约

- **入口**：一个可独立执行的程序（脚本或二进制），通过命令行参数或环境变量接收配置。
- **生命周期**：启动、执行、退出，不常驻、不监听端口。
- **输出**：业务日志可写 stderr；**stdout 最后一行必须是单个 JSON 对象**。
- **幂等**：同一输入重复执行不应产生不可逆的副作用；写操作必须可重放。

## stdout 契约

最后一行严格为：

```json
{"outcome":"success","summary":"一句话结果","artifacts":[],"error":null}
```

- `outcome`：三选一，`success` / `failure` / `skipped`。
- `summary`：字符串，供人和模型快速判读。
- `artifacts`：字符串数组，本程序产出的文件或资源标识；无产出时为空数组。
- `error`：`null` 或错误对象（结构见下）。

进程非零退出、最后一行不是合法 JSON、或字段结构不符 → 运行时按 `failure` 处理。

## 失败归因

失败时必须给出可行动的归因，不得只抛异常文本：

```json
{
  "outcome": "failure",
  "summary": "抓取阶段失败",
  "artifacts": [],
  "error": {
    "category": "dependency",
    "message": "上游接口返回 503",
    "retryable": true
  }
}
```

`category` 取值固定为以下之一：

| 类别 | 含义 |
|---|---|
| `input` | 输入缺失、格式错误或越界 |
| `environment` | 运行环境不满足（权限、路径、时钟） |
| `dependency` | 外部依赖不可用（网络、接口、第三方服务） |
| `logic` | 程序自身逻辑缺陷 |
| `timeout` | 超出允许的执行时长 |

`retryable` 必须明确：可重试的失败与不可重试的失败处理方式不同。

## 纪律

- **先自测再注册**：真实执行一次，确认退出码、最后一行 JSON 与业务结果均符合预期。
- **不吞错**：捕获异常后必须转成上述 `error` 结构，禁止打印后照常返回 `success`。
- **不写死调度**：何时运行由外部调度配置决定，程序本身不感知周期。
- **不在程序内做主观判断**：程序只负责执行与判读事实；需要决策时把结论写进 `summary`，交由上层处理。

## 验收清单

- [ ] 可独立执行，无隐藏的交互式输入
- [ ] stdout 最后一行是合法 JSON，且字段齐全
- [ ] `outcome` 与真实执行结果一致
- [ ] 失败路径带 `category` 与 `retryable`
- [ ] 重复执行不会产生不可逆副作用
- [ ] 已在真实环境自测通过
